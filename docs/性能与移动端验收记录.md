# 性能与移动端验收记录

## 一、自行设计的验收方法

PRD 要求“支持 200 人同时在线”和消息查询、发送、接收等核心操作小于 1 秒，但没有规定压测工具、持续时间、硬件型号或 200 人是否同时写入，属于需要自行设计的内容。

课程作业采用最简单且可复现的方案：在同一台 Windows 电脑上创建 200 个独立学生账号和登录会话，使用线程池同时请求同一活动课堂的讨论消息读取接口；随后连续 20 轮执行“学生发送文字—另一学生增量读取”。通过标准为 200 次并发读取全部成功，且并发读取、发送、增量接收的单次最大响应时间均小于 1 秒。测试使用一次性 `temp_perf_` 数据并在结束后按外键顺序清理。

## 七、传输与轮询优化复测

本轮维护进一步完成了以下优化：

- 实时统计改为在 SQLite 中按每名学生最新反馈聚合，接口最多读取六行分数段计数，不再把全班分数逐条传回 Python 后重复遍历。
- 教师统计和师生讨论轮询增加“请求进行中”保护，避免慢网络下出现重叠请求；浏览器标签页进入后台或对应工作台功能被隐藏时跳过轮询，重新可见后立即补读。
- 启用 GZip 响应压缩。使用本地 ECharts 6.1.0 文件实测，传输大小由 1,121,883 字节降至 369,405 字节，减少约 67.1%。
- API 和角色页面使用 `Cache-Control: no-store`；版本化第三方静态资源使用长期缓存，并增加 `nosniff`、禁止页面嵌入、来源与浏览器能力限制等响应头。

复测中，教师登录、当前课堂、实时统计和退出接口均返回 200，学生访问教师页面仍返回 403；当前课堂统计结果保持为 2 人、平均分 3.5、总体方差 2.25，与优化前一致。
