# 课堂学情监控管理系统安装调试手册

## 1. 运行环境

本项目按 Windows 10/11 课程作业环境设计，推荐 Python 3.11 或 3.12。浏览器推荐最新版 Edge 或 Chrome。项目不需要 Java、Spring Boot、MySQL、Vue 或 React。

主要依赖由 `requirements.txt` 管理：FastAPI、Uvicorn、SQLAlchemy、Pydantic、openpyxl、python-multipart。ECharts 已保存在项目本地，正常演示不依赖公共 CDN。

## 2. 安装步骤

### 2.1 检查 Python

在项目根目录 `D:\Projects\课堂学情监控管理系统` 打开 PowerShell：

```powershell
py --version
```

若提示找不到命令，请安装 Python，并在安装界面勾选“Add Python to PATH”。

### 2.2 创建虚拟环境并安装依赖

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

如果电脑安装的是 Python 3.11，把第一条命令改为 `py -3.11 -m venv .venv`。

如 PowerShell 禁止运行激活脚本，可跳过激活，后续命令统一写成 `.\.venv\Scripts\python.exe ...`。

## 3. 数据库初始化

### 3.1 正常初始化

项目已附带可运行的 SQLite 数据库。第一次在新目录运行或缺少数据库时，执行：

```powershell
python -m scripts.init_db
```

该命令使用 SQLAlchemy 创建缺失表，并补充最小演示账号、测试课程、活动课堂和统计配置；重复执行不会重复创建相同账号或课堂，也不会清空当前运行数据库中的新增用户和业务记录。

### 3.2 完整 SQL 脚本

`database/schema.sql` 是完整的 10 表建表脚本，`database/seed.sql` 是可重复导入的完整演示数据。两者用于课程提交、数据库设计检查和从空库恢复演示环境。导入顺序必须是：

```text
schema.sql → seed.sql
```

SQL 基线数据包括 4 个账号、1 门课程、1 个活动课堂、3 条反馈、1 条统计快照、2 条讨论消息和 1 条已处理预警。当前随项目保存的运行数据库已经扩充到 16 个账号、3 门课程和 3 节课堂；详情见《[当前演示数据说明](当前演示数据说明.md)》。所有测试账号初始密码为 `123456`，密码在数据库中以 PBKDF2-SHA256 散列保存。

## 4. 启动与停止

依赖和数据库准备完成后，可双击 `run.bat`，或执行：

```powershell
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

看到 `Uvicorn running on http://127.0.0.1:8000` 后访问：

- 系统首页：<http://127.0.0.1:8000>
- 健康检查：<http://127.0.0.1:8000/api/health>
- 接口文档：<http://127.0.0.1:8000/docs>

停止服务时回到终端按 `Ctrl+C`。不要在服务仍运行时直接覆盖数据库文件。

## 5. 配置与数据位置

| 内容 | 位置或说明 |
| --- | --- |
| 主数据库 | `database/classroom_monitor.db` |
| 隔离数据库 | 可临时设置 `CLASSROOM_MONITOR_DATABASE` 为另一 SQLite 文件路径；未设置时仍使用主数据库 |
| 数据库运行辅助文件 | `classroom_monitor.db-wal`、`classroom_monitor.db-shm`，服务停止后会自动处理 |
| 上传图片 | `frontend/static/uploads/discussions/{课堂编号}/` |
| ECharts | `frontend/static/vendor/echarts/echarts.min.js` |
| 统计周期 | 数据库 `statistics_settings` 表，管理员页面设置 5～10 分钟 |
| 实时统计刷新 | 前端每 5 秒读取，不等于历史快照周期 |
| 讨论消息刷新 | 前端每 3 秒增量读取 |
| 桌面工作台 | 浏览器宽度不小于 1024px 时使用固定左侧导航，一次显示一个功能区 |
| 窄屏工作台 | 小于 1024px 时使用顶部横向功能标签 |

## 6. 数据备份与恢复

课程演示前先停止服务，把下面内容复制到安全位置：

- `database/classroom_monitor.db`
- `frontend/static/uploads/`

恢复时同样先停止服务，再替换数据库与上传目录。SQLite 的 WAL 模式支持并发读取，但运行中的 `.db`、`.db-wal`、`.db-shm` 属于一组文件，不能只随意复制其中一个。最终打包脚本会在服务停止后只提交主数据库并排除临时 WAL 文件。

## 7. 常见问题与最小修复

### 7.1 `No module named fastapi` 或其他模块缺失

原因通常是没有安装依赖，或终端没有使用项目的 `.venv`。执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 7.2 端口 8000 被占用

先关闭旧的 Uvicorn 终端。若必须临时换端口：

```powershell
python -m uvicorn backend.app.main:app --reload --port 8001
```

浏览器地址也要改成对应端口。

### 7.3 短信验证码按钮无反应

1. 必须通过 `http://127.0.0.1:8000` 打开，不要直接打开 `frontend/index.html`。
2. 按 `Ctrl+F5` 强制刷新旧的 CSS/JavaScript 缓存。
3. 点击“短信验证码”页签后再输入已登记手机号。
4. 查看 Uvicorn 终端是否有红色报错；健康检查应返回 `status: ok`。
5. 课程演示码显示在页面提示中，不会送到真实手机。

### 7.4 页面能打开但图表空白

确认 `frontend/static/vendor/echarts/echarts.min.js` 存在，登录的是 `teacher001`，并且活动课堂有学生反馈。按 `Ctrl+F5` 后查看浏览器开发者工具 Console 是否有错误。

### 7.5 历史查询暂时没有新记录

统计周期只能设为 5～10 分钟。后台约每 30 秒检查一次，但每个完整周期只写入一条快照。设置为 6 分钟时，等待的是一个完整的 6 分钟窗口，不是每 30 秒写一条；旧快照不会因修改周期而删除。管理员页面的近 7 天趋势来自 `statistics_snapshots` 的真实日期聚合，进行中课堂数来自 `course_sessions`，不需要新增数据库表。

### 7.6 `database is locked`

先停止重复启动的 Uvicorn 进程和打开数据库的编辑器，再启动一个服务。项目已配置 WAL、30 秒连接超时和 `busy_timeout`。不要同时用多个程序长时间开启写事务。

### 7.7 图片上传失败

只允许真实 JPEG、PNG、GIF、WebP，最大 5 MB。系统根据文件头判断格式，修改扩展名不能把普通文件伪装成图片。还要确认项目目录具有写权限。

### 7.8 Excel 没有下载或打不开

确认安装了 openpyxl；先在历史页完成查询，再点击“导出当前结果”。浏览器可能把下载放在默认“下载”目录。若查询条件非法或无权限，接口会返回错误而不是损坏的工作簿。

## 8. 验收检查命令

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m scripts.smoke_test
.\.venv\Scripts\python.exe -m scripts.validate_submission
```

第一条检查统计截止时间与完整周期快照，第二条在临时数据库上启动真实 HTTP 服务并执行 42 项登录、权限、认证、页面和响应头冒烟验收，第三条检查 26 项必备文件、11 张截图、37 个 Markdown 本地链接、35 个前端静态资源引用、60 个 Python 文件语法和数据库基线。三条命令均不会改动运行数据库。

最终打包前还可以手动运行严格模式：

```powershell
.\.venv\Scripts\python.exe -m scripts.validate_submission --strict
```

严格模式会把姓名、学号、班级、签字日期等个人信息占位符视为失败。`scripts/package_submission.ps1` 已自动调用该模式，因此未填写完整时不会生成 ZIP。

自动检查之外，还应人工检查六档反馈、图表、历史查询、Excel、文字/图片讨论、课程与课堂管理、用户管理、统计周期、学情预警、桌面功能导航和手机宽度。详细证据见 `docs` 目录中的各阶段验收记录与 `截图与视频` 目录。

## 9. 生产化边界

真实短信供应商、真实微信/QQ 开放平台、HTTPS、域名、云服务器、反向代理和多机数据库没有在 PRD 中明确规定，属于需要自行设计的内容。本课程作业采用本地模拟第三方登录和 SQLite，便于离线展示并符合固定技术栈。若未来上线，应更换真实凭据管理、HTTPS、安全审计与生产数据库方案，但不应把这些额外内容混入本次基础需求。
